
# Табличные представления для просмотра файлов протоколов СУБД в формате CSV

## Проблема
1. В `Postgres` протоколы работы (логи) сервера СУБД обычно сохраняются в отдельные текстовые файлы (в формате `log` или `csv`).
1. Для анализа проблем из файлов удобно выбрать нужные строки командами ОС (`grep`, [`rg`](https://github.com/burntsushi/ripgrep)) через поиск подстрок.
1. Для доступа сотрудников к файлам необходимо `SSH` подключение к серверу СУБД. 
   По соображениям безопасности в промышленной среде такой доступ очень ограничен.   
   Чтобы забрать файлы для анализа, нужно согласование отдела ИБ и участие сисадминов.
1. В крупных компаниях настраивают непрерывную отгрузку последних изменений из файлов 
   в другую систему для возможности индексирования и быстрого поиска информации уже там.
   Это удобно, но есть ограничения: 
   * требуются дополнительные вычислительные ресурсы и сопровождение;
   * последние данные появляются в результатах поиска не сразу, а с задержками (десятки секунд);
   * есть риск сбоя или отказа ещё одной системы.

## Решение
1. Имеется возможность читать всегда актуальные данные из файлов в формате `csv` (включая сжатые архивы) через _**табличные представления**_.
1. По сравнению с файлами, у табличных представлений появляются следующие дополнительные возможности и преимущества: 
   * Точечный и сложный анализ протокола работы сервера СУБД на `SQL` через `SELECT` запросы. 
     Пример: выборка нужных колонок, фильтрация, группировка, агрегация, сортировка.
   * Управление доступом сотрудникам только к табличным представлениям (без доступа к другим базам и таблицам) через отдельные учётные записи СУБД.
   * Отсутствует необходимость `SSH` доступа на сервер СУБД.

## Настройка параметров сервера 

В конфигурационном файле СУБД нужно настроить сохранение протоколов в формате `CSV`:
```
log_destination = 'csvlog'
```
